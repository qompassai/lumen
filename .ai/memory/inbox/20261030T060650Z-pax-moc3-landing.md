## Port deltas beyond wiring (each named, none silent)

1. `ayagami` dev-dependency dropped (it lives in the torogao
   tree; a landed crate cannot path-depend outside the repo).
   The two ayagami tests were adapted, not silently deleted:
   `ayagami_parses_the_exported_fixture` became
   `own_parser_reads_the_exported_fixture` (same id assertions
   through the crate's own parser; MAPPING.md gate (b) is
   documented as not covered in this repo), and
   `ayagami_parses_the_official_haru_sample_as_a_control` was
   removed (its in-repo analogue, the conversion-side Haru
   test in validation.rs, survives).
2. External-fixture tests in tests/inp.rs (Aka.inx from the
   torogao fixtures tree; E2-emitted Aka.moc3 from the
   moc3-export workspace) now skip when the fixture is absent,
   following validation.rs's official-sample pattern, instead
   of hard-failing; the ayagami layer of the E2 test was
   removed for the same reason as (1). In the lumen tree these
   tests pass vacuously; at full force they ran green in the
   source tree. Vendoring the Aka fixture into this repo is
   the open follow-up if the pins are wanted at full force.
3. Clippy 0.1.100 (estate pin nightly-2026-09-25) flagged
   three `needless_range_loop` sites the source tree's stable
   clippy did not; rewritten as enumerate loops with identical
   semantics (src/convert/inp.rs ×2, tests/export.rs ×1).

## rig-core TEXTURES_MAX alignment (separate commit)

The converter was built against the rig runtime line where
SPEC section 11 was amended 2026-10-26 raising TEXTURES_MAX
64 -> 256 (real INP puppets exceed 64 slots; the Aka fixture
references 76). The landed rig-core still carried 64 in both
`crates/lumen-rig-core/src/limits.rs` and the SPEC.md table.
Aligned to 256 with the amendment provenance in a comment;
no rig-core test pinned the old value (the LRF-107 adversarial
test pins the parameter bound, not textures).
